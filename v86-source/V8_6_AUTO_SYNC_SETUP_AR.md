# مخزني V8.6 — تشغيل المزامنة التلقائية

## ما الذي تفعله هذه المرحلة؟
- يفحص كل جهاز السحابة كل 5 ثوانٍ عندما يكون التطبيق مفتوحاً، والموظف المحلي مسجلاً للدخول، والاتصال متاحاً.
- إذا تغيّرت بيانات الجهاز وحده، يحفظ التطبيق لقطة بيانات معلّقة محلياً ثم يرفعها باستخدام رقم المراجعة.
- إذا تغيّرت السحابة وحدها، ينشئ التطبيق نسخة أمان محلية ثم يستقبل النسخة السحابية، مع الإبقاء على PIN المحلية.
- إذا تغيّر الجهاز والسحابة معاً، يوقف التطبيق المزامنة الآلية ويطلب اختيار النسخة التي ستُعتمد.
- لا يدمج المبيعات أو حركات المخزون تلقائياً؛ تجنباً لتكرار الكميات أو الأرباح.

## تفعيل آمن
1. احتفظ بنسخة JSON احتياطية مستقلة من الجهاز الرئيسي.
2. طبّق مرة واحدة ملف SQL:
   `supabase/migrations/202611260001_snapshot_write_safety.sql`
   في SQL Editor داخل مشروع Supabase الحالي. لا تعِد تشغيل Migration القديم ولا تنشئ مشروعاً جديداً.
3. ثبّت النسخة المحدّثة على الجهاز الرئيسي وافتح «المزيد» ثم «المزامنة السحابية».
4. سجّل الدخول بحساب المالك نفسه، ثم ارفع بيانات الجهاز الرئيسي مرة واحدة. هذه الخطوة تنشئ خط الأساس الذي تعتمد عليه المزامنة التلقائية.
5. على الجهاز الثاني، ثبّت النسخة وسجّل الدخول إلى حساب Supabase المرتبط بالمتجر نفسه، ثم نزّل النسخة السحابية مرة واحدة بعد حفظ نسخة احتياطية محلية.
6. بعد الإعداد الأولي، تعمل المزامنة تلقائياً كل 5 ثوانٍ أثناء تشغيل التطبيق. لا تجرِ مبيعات متزامنة على الجهازين قبل اختبار النسخة الجديدة على بيانات تجريبية ونسخ احتياطية.

## حدود معروفة
- هذه مزامنة تلقائية دورية (كل 5 ثوانٍ)، وليست بثاً لحظياً عبر Supabase Realtime.
- اللقطة المعلقة تحفظ آخر حالة محلية كاملة؛ لا توجد بعد قائمة أحداث معاملات منفصلة.
- عند تعديل الجهازين منذ آخر مزامنة، يلزم حسم التعارض يدوياً. لا تستخدم الدمج التلقائي للبيانات المالية أو المخزون.
- PIN الموظفين تبقى محلية ولا تنتقل بين الأجهزة.
- لم يتم اختبارها بعد على جهاز Windows وجهاز Android فعليين، ولم يتم إصدار مثبت Windows أو APK من هذه التعديلات.

## استعادة نسخة الأمان
قبل تنزيل سحابي تلقائي أو حل تعارض باعتماد السحابة، تحفظ نسخة أمان JSON داخل تخزين التطبيق المحلي. لا تمسح بيانات التطبيق أو مساحة التخزين قبل تصدير نسخة أمان مستقلة.
