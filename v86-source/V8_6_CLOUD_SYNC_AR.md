# مخزني POS V8.6 — مرحلة ربط Supabase التجريبية

## ما أُضيف
- صفحة «المزامنة السحابية» من قائمة «المزيد» للمالك.
- تسجيل الدخول ببريد وكلمة مرور Supabase Auth.
- اكتشاف المتجر المرتبط بحساب المالك تلقائياً؛ لا حاجة لنسخ Store ID.
- رفع نسخة بيانات الجهاز إلى مخزن Supabase أو تنزيل النسخة السحابية إلى الجهاز باختيار صريح.
- استخدام رقم مراجعة snapshot لمنع الكتابة فوق نسخة أحدث إذا حدث تعارض أثناء الحفظ.
- عدم رفع PIN الموظفين إلى السحابة؛ تبقى أرقام PIN محلية على كل جهاز.
- لا يتم حذف أو تعديل البيانات المحلية عند مجرد تسجيل الدخول.
- إعداد GitHub Actions لبناء مثبت Windows.

## ما لم يكتمل بعد
هذه ليست مزامنة فورية تلقائية متعددة الأجهزة. النقل الحالي يدوي باتجاه واحد في كل مرة (رفع أو تنزيل). لا توجد بعد قائمة انتظار عمليات Offline، أو دمج أحداث المبيعات المتزامنة، أو خادم Wi-Fi محلي، أو إدارة آمنة لموظفي Supabase وربط أدوار التطبيق. لا تستخدم جهازين لإجراء مبيعات متزامنة اعتماداً على هذه المرحلة وحدها.

## إعداد Supabase
قاعدة البيانات أُنشئت بالفعل من ملف SQL سابقاً. لا تعِد تشغيل Migration إلا إذا كنت تهيئ مشروعاً جديداً. بيانات المشروع داخل `lib/supabaseSync.ts`:
- Project URL: `https://qqwpcculkdeitwksgvzn.supabase.co`
- Publishable key: مفتاح `sb_publishable_...` فقط، وهو مفتاح عميل عام.

لا تضف أبداً `service_role` أو Secret key إلى التطبيق أو GitHub.

## طريقة الاستخدام بعد تثبيت البناء
1. افتح مخزني وسجل الدخول المحلي كالمعتاد.
2. افتح «المزيد» ثم «المزامنة السحابية».
3. أدخل بريد وكلمة مرور مستخدم Supabase الذي أنشأته.
4. سيبحث التطبيق عن المتجر المرتبط بهذا الحساب تلقائياً.
5. على الجهاز الرئيسي، اختر «رفع بيانات هذا الجهاز إلى السحابة» بعد أخذ نسخة احتياطية محلية.
6. على جهاز آخر، سجّل الدخول بحساب Supabase نفسه، ثم اختر «تنزيل بيانات السحابة إلى هذا الجهاز» بعد التأكد من أن بياناته المحلية محفوظة في نسخة احتياطية.

ملاحظة: تنزيل السحابة يستبدل بيانات التطبيق على الجهاز الحالي. أرقام PIN لا تنتقل بين الأجهزة؛ يحتفظ كل جهاز بأرقام PIN المحلية الموجودة لديه. الموظفون الجدد على جهاز آخر يحتاجون إلى ضبط PIN محلياً قبل استعمال تسجيل الدخول المحلي.

## بناء Windows من GitHub
1. ارفع محتويات هذا الأرشيف إلى جذر المستودع (مع المجلدات المخفية مثل `.github`).
2. افتح Actions في GitHub.
3. اختر `Build Makhzani POS V8.6 for Windows` ثم `Run workflow`.
4. عند نجاح البناء افتح Artifacts وحمّل `Makhzani-POS-V8.6-Windows-Installer`.

هذا الأرشيف مصدر المشروع، وليس ملف EXE مبنياً. لم يتم تنفيذ بناء Windows داخل بيئة إعداد هذا الملف؛ يجب التأكد من نجاح GitHub Actions قبل تثبيت النسخة.
